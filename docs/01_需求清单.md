# 考研英语作文批改自研Agent - 需求清单

---

## 1. 技术架构选型
| 层级 | 选型 | 说明 |
|------|------|------|
| **后端框架** | Spring Boot 3.x + Spring Data JPA | Java生态成熟，便于团队维护，JPA简化数据库操作 |
| **前端框架** | Vue 3 + Element Plus | 组件化开发，Element Plus提供完整UI组件库 |
| **数据库** | MySQL 8.0 + Redis 7.x | MySQL持久化历史记录，Redis缓存会话数据 |
| **OCR服务** | 百度OCR通用文字识别API | 准确率高，费用低廉，支持手写识别 |
| **大模型** | Claude API (claude-3-5-sonnet-20241022) | 中文理解能力强，结构化输出稳定 |
| **部署方案** | Docker + Docker Compose | 单机部署，简化运维，支持快速回滚 |
| **前端持久化** | localStorage | sessionId存储在localStorage，刷新页面后自动恢复 |

---

## 2. 项目背景

本项目为面向考研备考学生的英语作文辅助批改工具，基于Claude自研简易Agent实现，不使用任何现成Agent框架。

**核心价值**：帮助学生快速完成作文打分、错误定位、润色优化与范文参考，支持手写作文拍照识别批改，同时提供模拟题生成能力，辅助日常写作练习。

**定位**：Agent为业务辅助工具，专注考研英语作文场景，不做通用闲聊Demo。

---

## 3. 术语定义
| 术语 | 定义 |
|------|------|
| **会话（Session）** | 由一个sessionId标识的完整用户使用周期，包含多篇作文的多次交互，数据存储于Redis，有效期7天 |
| **对话轮次（Turn）** | 一轮 = 用户一次请求 + Agent一次响应构成的完整交互单元；仅统计Agent成功响应的轮次，用户连续发送多条消息但仅获得一次响应时计为一轮 |
| **作文（Essay）** | 一次批改任务的主体，包含题目、原文、批改结果；一篇作文可经历多轮迭代批改 |
| **词（Word）** | 按空格、标点、emoji分割的英文单词单元；连续英文字母序列计为一个词 |
| **作文类型枚举** | 统一为三种：`EN1_PICTURE`（英语一图画大作文）、`EN2_CHART`（英语二图表大作文）、`LETTER`（应用文/小作文，英语一与英语二评分标准一致，不做区分） |

## 4. 用户角色
- **匿名用户**：无需注册登录，通过前端生成的sessionId标识会话，所有数据与会话绑定。
- 账号注册登录体系为预留扩展能力，当前版本不实现。

## 5. 核心功能清单

### 4.1 随机模拟题目生成
- 支持选择作文类型：英语一图画大作文（EN1_PICTURE）、英语二图表大作文（EN2_CHART）、应用文/小作文（LETTER）
- **作文类型为必选项，未选择时前端禁用生成按钮**
- 由大模型实时生成全新模拟考题，不从本地题库抽取，避免局限于历年真题
- 输出内容包含题目描述、写作要求、词数要求
- 生成的题目自动带入当前会话上下文，后续批改无需重复输入题目；**新生成的题目覆盖会话中上一个题目，同一时刻会话中仅保留一个"当前题目"**
- **生成题目时使用高Temperature（1.0，为对应模板的默认配置值，可通过模板版本管理调整）保证题目创意多样性**

### 4.2 自定义题目生成范文
- 用户手动输入作文题干，选择作文类型
- **题干非空校验：去除首尾空白后长度≥5字符，否则提示"请输入作文题目"**
- Agent生成符合考研评分标准的参考范文
- 支持基于范文继续追问润色、句式优化
- **生成范文时使用低Temperature（0.6，为对应模板的默认配置值，可通过模板版本管理调整）保证输出稳定高质量**
- **所选作文类型将写入当前会话，作为后续批改的默认类型；若后续批改时未重新选择则沿用该类型，避免评分标准错配**

### 4.3 文本输入作文批改
- 用户粘贴作文原文，选择对应作文类型
- **类型继承规则**：自动携带当前会话中已设定的作文类型（来自4.1题目生成或4.2自定义输入）作为默认值；若会话中无设定类型（用户直接粘贴作文未经过4.1/4.2），则要求用户手动选择类型后方可提交；用户可随时手动覆盖
- **输入前置校验（拦截式，不通过则拒绝提交）**：
  1. 非空校验：去除首尾空白后长度≥10字符
  2. 语言检测：英语字符（a-z, A-Z）占比≥80%；分母=英语字符数+非英语字母字符数（中文、日文等），标点、数字、空格、emoji既不计入分子也不计入分母；不满足则拦截并提示"请提交英语作文"
  3. 长度上限：单篇作文不超过800词（按空格+标点+emoji分割统计），超出提示"请精简至800词以内"
  4. 非法内容检测：使用开源轻量级敏感词库进行前置拦截，含敏感词/恶意代码注入时拒绝处理；v1.1增加误杀申诉机制
- **特殊字符处理**：表格、代码块、emoji在语言检测中不计入英语字符；词数统计时emoji和特殊符号视为分隔符
- Agent按照考研官方作文评分标准输出批改结果，包含：
  1. 总分及分项得分（内容完整性、语言准确性、词汇多样性、句式丰富度）
  2. 语法错误与用词错误定位
  3. 现存不足与修改建议
  4. 全文润色优化版本
  5. 可复用高级句型与表达提炼
- 批改结果默认以JSON结构化形式直接返回前端展示，用户提交后即可查看

### 4.4 图片OCR手写作文批改
- 支持上传手写作文图片
- **图片上传限制**：支持jpg、png、jpeg格式，单张图片大小不超过10MB，建议图片宽度不低于1000px以保证OCR识别准确率；超出限制时前端拦截并提示压缩后重试
- **上传失败处理**：网络超时或存储服务不可用时，提示"图片上传失败，请检查网络后重试"，支持重新上传，不降级
- 调用第三方OCR接口识别图片中的作文文本
- **OCR异常处理**：OCR服务返回空结果或乱码时，自动重试1次；仍失败则提示"图片识别失败，请手动输入文本"，降级到纯文本输入模式
- **OCR识别结果校验（仅提示不拦截，允许校对后继续）**：
  1. 语言检测：英语字符占比低于80%时，提示"识别结果可能非英语内容，请校对修正后再提交"，但不阻断提交
  2. 长度校验：识别文本长度低于10字符时，提示"识别内容过短，请确认图片清晰度"
- **OCR特殊字符**：识别结果中夹杂的数学符号、下划线等特殊字符在前端校对框中正常显示，不做特殊过滤
- 识别结果返回前端，支持用户人工校对修正识别错误
- 校对确认后提交作文，**执行4.3定义的输入前置校验（拦截式）**，校验通过后执行批改流程
- 批改记录关联保存原始图片地址
- **校对校验**：提交时比对OCR原始识别文本与用户校对后文本的编辑距离，若改动超过30%，提示用户"改动较大，是否以当前文本为准？图片仅作参考"，并在记录中标记is_heavily_edited=true
- **重度编辑差异化处理**：标记为is_heavily_edited的记录，批改时Prompt中降低图片参考权重，记录详情页显示"非原图批改"标签

### 4.5 多轮迭代批改
- 支持同一篇作文多轮修改、多次批改
- 自动携带历史对话上下文，无需重复粘贴题目与原文
- **上下文截断采用滑动窗口策略**：
  - 固定保留：System Prompt + 当前题目 + 当前待批改作文 + 最近2轮完整对话
  - 当对话轮次超过4轮时，将第1轮至第(N-2)轮的对话内容交由Agent生成历史摘要，摘要替换原始记录参与后续调用
  - 每次触发截断时**重新生成完整摘要（覆盖式）**，不做增量更新，降低实现复杂度；摘要生成在当前请求内同步完成，摘要生成的Token消耗计入本次请求总消耗
  - **摘要生成失败降级**：摘要生成超时或失败时，降级为直接截断策略——丢弃最早的两轮对话（保留最近4轮完整对话），确保批改流程继续；同时在响应中标记 `summary_degraded: true`，前端提示"部分历史会话摘要生成失败，已自动精简上下文"
  - **响应时间说明**：触发摘要生成的轮次需连续执行两次大模型调用（摘要生成+作文批改），响应时间可能超过10秒目标，10秒响应目标仅适用于未触发摘要生成的常规轮次
- **单会话最大迭代轮次上限为10轮**，达到上限后提示"已超出本轮对话最大迭代次数，建议清空上下文重新开始"

### 4.6 会话管理
- **sessionId由前端生成（UUID v4），通过请求头 X-Session-Id 传递给后端**；后端不主动创建session，仅根据前端传入的sessionId进行数据读写
- **sessionId合法性校验**：后端校验UUID v4格式，格式不合法或为空时返回400错误，前端重新生成sessionId
- 基于sessionId维护独立会话，对话轮次上下文存储于Redis（临时缓存）
- 支持手动清空当前会话上下文，主动释放Token
- **"清空当前会话上下文"仅清除Redis中的对话轮次记录（用于释放Token），不影响已持久化到MySQL的历史批改记录（4.8）**；两者存储介质物理隔离，清空上下文后历史记录查询接口仍可正常返回数据；当前版本不实现历史记录删除功能
- 会话有效期7天，过期后Redis数据自动清理
- **会话过期检测**：后端所有接口响应中统一携带 `X-Session-Status` 响应头，值为 `active` 或 `expired`；前端检测到 `expired` 时，弹窗提示"会话已过期，请重新开始练习"并清除本地会话状态，引导用户重新开始
- **会话过期与图片存储对齐设计**：会话有效期7天与图片存储有效期7天对齐；会话过期后，历史记录查询接口**不校验会话状态**，只要sessionId格式合法即可查询；但关联图片可能已过期，前端显示占位缩略图

### 4.7 批改报告导出
- 支持将完整批改结果导出为Markdown格式报告（附加功能，非唯一输出方式）
- 报告包含：题目、学生原文、得分、错误点、修改建议、润色范文、高级句型
- **Markdown报告由前端基于JSON批改结果结构化渲染生成，无需后端额外调用Agent生成**，确保导出内容与展示内容一致，避免二次生成增加Token消耗和内容不一致风险
- **图片处理**：Markdown报告不嵌入原图，仅保留图片URL链接（图片7天过期后链接失效）
- **导出时对Markdown内容进行净化（Sanitize）处理**，过滤javascript:等危险协议，防止XSS

### 4.8 历史记录
- 每次批改的题目、原文、批改结果、图片地址、template_id、template_version、创建时间持久化存储于MySQL
- 支持按sessionId查询历史批改记录，**支持分页，默认每页20条**
- **支持历史记录"重新批改"**：用户可在历史详情页将历史原文+原题目重新送入Agent批改；"重新批改"视为独立的批改任务：
  - 默认复用原记录的作文类型，用户可在提交前修改
  - 不继承原作文的迭代上下文（争议标注等作文级数据重置）
  - **不清空session级词汇集**（词汇集为session级别，跨作文共享，重新批改不影响当前会话其他作文的词汇集）
  - 仅复用题目与原文，生成一条全新的历史记录，便于用户对比不同版本的得分差异
  - **"重新批改"视为一次新的批改请求，计入单session每分钟5次的限流配额**

### 4.9 评分标准动态适配
- 建立作文类型与评分维度的映射关系，不同类型注入不同评分权重：
  - EN1_PICTURE（英语一图画大作文）：侧重图画描述准确性、寓意提炼深度
  - EN2_CHART（英语二图表大作文）：侧重图表数据分析、趋势归纳能力
  - LETTER（应用文/小作文）：侧重格式规范、交际得体性、信息完整性
- **考研英语一与英语二小作文评分标准基本一致**（格式要求、词数要求100词左右、评分维度相同），统一使用LETTER类型，不做区分
- Prompt模板根据用户选择的作文类型动态注入对应评分标准与权重，确保打分维度与考研官方一致

### 4.10 生词/好词收藏（v1.0预留数据结构，v1.1启用）
- v1.0实现基础数据结构：Redis存储当前session的词汇集（session级别，跨作文共享），批改记录预留相关字段
- **前端暂不暴露"加入生词本"交互入口**，预留数据结构供后续v1.1迭代启用，避免后期加字段需要数据迁移
- v1.1规划：
  - 暴露"加入生词本"交互入口
  - 仅在同一会话（sessionId）的后续迭代轮次中生效，在Prompt中附加"您之前收藏过XX表达，本次可尝试使用"
  - 提供生词本查询接口，支持查看当前会话已收藏的词汇
  - 不做跨会话词汇集复用

### 4.11 批改结果争议标注（v1.0预留数据结构，v1.1启用）
- v1.0实现基础数据结构：批改记录预留user_disputed字段（作文级别，绑定单篇作文）
- **前端暂不暴露"我认为此处无误"交互入口**，预留数据结构供后续v1.1迭代启用
- v1.1规划：
  - 暴露"我认为此处无误"交互入口
  - 用户标注不影响本次总分，记录user_disputed状态
  - 仅在同一篇作文的后续多轮修改中携带该争议标注，提示Agent"用户上一次不同意某处修改，请重新审视"
  - 新开作文时重置，避免历史争议污染新作文批改逻辑
  - 提供争议标注查询接口

### 4.12 Prompt模板版本管理
- 所有Agent调用所使用的System Prompt、User Prompt、评分维度Prompt均以模板形式存储，支持模板ID标识
- 每个模板包含：模板名称、版本号、模板内容、适用作文类型、Temperature默认值、是否启用
- **模板内容支持变量占位符语法**（如 `{{essay_type}}`、`{{user_essay}}`、`{{history_summary}}`、`{{topic}}`），调用时由Agent调度层完成变量替换后送入大模型；模板以纯文本格式存储，占位符解析由后端处理，不引入第三方模板引擎
- 接口调用时通过template_id指定使用哪个版本的Prompt
- **灰度规则**：按 `hash(sessionId) % 100` 取模分流，配置化指定灰度百分比；每个会话首次调用时根据灰度规则锁定模板版本，该会话后续所有请求均沿用同一版本，不受灰度规则变更影响，避免同一会话内模板版本切换导致评分不一致
- **批改记录中需保存本次所使用的template_id和template_version，便于效果回溯**
- 新增模板版本不覆盖旧版本，便于回滚与效果对比
- 当前版本仅实现模板配置化存储与加载（Redis/配置文件），不做可视化编辑后台，通过配置文件/Redis手动管理
- 后续调优Prompt时无需重启服务即可切换，为未来"不同评分策略对比实验"预留基础

## 6. 核心业务流程

### 路径A：随机模拟题练习流程
1. 用户选择作文类型，请求生成模拟题目（高Temperature=1.0）
2. Agent调用大模型生成全新模拟考题，返回给用户，类型写入会话
3. 用户完成写作，通过文本粘贴 / 图片上传提交作文
4. 输入前置校验通过后，Agent执行批改，返回完整结构化批改结果
5. 用户可基于结果继续修改作文，多轮迭代（最多10轮）

### 路径B：自定义题目练习流程
1. 用户输入作文题目，选择类型，类型写入会话
2. 用户可选择：直接生成参考范文（低Temperature=0.6） / 提交自己写的作文进行批改
3. Agent执行对应任务，返回结果
4. 支持多轮继续润色、修改

### 路径C：纯文本直接批改（无题目生成）
1. 用户直接粘贴作文原文，会话中无设定类型
2. 系统要求用户手动选择作文类型
3. 输入前置校验通过后，Agent执行批改，返回结果

## 7. 非功能需求
1. **Token控制**：通过滑动窗口上下文截断、Prompt模板化、输入精简策略控制单次调用Token消耗，避免无限制投喂全文
2. **容错性**：OCR识别失败、大模型调用超时/限流、返回格式异常时，给出友好提示并提供降级方案
3. **降级策略**：
   - OCR服务不可用时，自动降级为纯文本输入模式
   - 大模型返回格式异常时，自动重试1次且将Temperature降至0.1；若仍失败则降级返回"仅语法纠错"的简化版结果
   - 大模型输出内容超长时，设置max_tokens限制，超出部分截断并提示，前端做折叠展示
4. **安全性**：输入参数校验，防止非法内容；API密钥配置化管理，不硬编码；Markdown导出内容做XSS净化
5. **响应速度**：单次批改平均响应时间控制在10秒内
6. **并发与限流**：
   - 限流：单session每分钟请求数上限5次，**仅针对调用大模型的接口（生成题目、生成范文、作文批改、重新批改）计入配额**；超出返回429状态码；查询历史记录、清空上下文、导出报告等非大模型调用接口不限流
   - 并发控制：同一sessionId的请求需串行化处理，通过Redis分布式锁（锁key=`lock:session:{sessionId}`，超时60秒）保证同一时刻仅一个请求在执行；后续请求排队等待，锁超时后返回"当前有批改任务正在处理，请稍后重试"，避免多请求并发读写上下文导致数据覆盖错乱
   - 两者关系：并发控制保证同一时刻只有一个请求执行，限流保证单位时间内请求总数不超限，两者独立生效
7. **图片存储有效期**：OCR原始图片存储有效期7天，过期后前端显示占位缩略图，避免存储成本无限膨胀
8. **日志与监控**：记录Agent调用成功率、平均响应时间、单次/累计Token消耗、OCR识别成功率、模板版本分布；调用失败率超过阈值时触发告警
9. **数据备份与恢复**：MySQL历史记录定期备份；Redis会话数据为临时缓存，丢失不影响持久化历史记录，用户体验上表现为对话上下文丢失但历史批改仍可查询

## 8. 明确不实现的功能（需求取舍）
- ❌ 不实现用户注册、登录、账号管理体系，采用匿名会话机制，账号体系为预留扩展
- ❌ 不本地维护海量真题题库，随机题目由大模型实时生成，不做题目库CRUD
- ❌ 不自主训练OCR模型，依赖第三方OCR接口，识别错误通过人工校对修正
- ❌ 不支持多模态识别（如图表中具体数值的OCR提取），图表作文的"数据描述"依赖用户自行从图片中提取填入，系统仅识别手写文字内容
- ❌ 不支持通用闲聊对话，仅处理考研英语作文相关任务，非相关输入予以拦截提示
- ❌ 不使用LangChain、Superpowers等任何现成Agent框架，全部自行封装ClaudeCode调用与调度逻辑
- ❌ 不实现作文收藏、标签分类、点赞等额外CRUD功能，聚焦Agent核心能力
- ❌ 不做复杂前端页面美化，重点为后端Agent逻辑与接口实现
- ❌ 当前版本不实现历史记录删除功能
- ❌ 当前版本不实现敏感词误杀申诉机制（v1.1规划）

## 9. 项目边界
- 本项目核心亮点为**自研Agent调度逻辑、Token上下文截断（滑动窗口+摘要覆盖式生成）、Prompt模板化与版本管理、大模型结果解析与容错降级**
- 所有业务功能围绕Agent展开，不做脱离Agent的纯CRUD后台管理系统
- AI输出结果仅作辅助参考，不保证完全符合阅卷评分，核心能力为辅助练习
