# 考研英语作文批改自研 Agent — 总体方案

> 版本：v1.0　|　日期：2026-08-26　|　对应需求：`01_需求清单.md`

---

## 1. 项目概述

面向考研备考学生的英语作文辅助批改工具。基于 **Claude API 自研简易 Agent**（不使用 LangChain 等现成框架），实现作文打分、错误定位、润色优化、范文参考，并支持手写作文拍照 OCR 识别批改与模拟题生成。

**核心价值**：快速完成作文打分 → 错误定位 → 润色 → 范文参考，辅助日常写作练习。

**项目定位**：Agent 为业务辅助工具，专注考研英语作文场景，不做通用闲聊 Demo。

## 2. 总体技术架构

| 层级 | 选型 | 选型理由 |
|------|------|----------|
| 后端框架 | Spring Boot 3.x + MyBatis-Plus | Java 生态成熟，MyBatis-Plus 简化 CRUD 操作，贴合简历技术栈 |
| 前端框架 | Vue 3 + Element Plus | 组件化开发，Element Plus 提供完整 UI 组件库，降低开发成本 |
| 数据库 | MySQL 8.0（持久化）+ Redis 7.x（会话缓存） | MySQL 成熟稳定，Redis 兼作缓存/分布式锁/限流计数/模板缓存，一物多用 |
| OCR 服务 | 百度 OCR 通用文字识别 API | 手写文字识别准确率高，新用户有免费额度，API 接入简单 |
| 大模型 | Claude API (`claude-3-5-sonnet-20241022`) | 中文理解能力强，结构化输出稳定，价格合理 |
| 部署 | Docker + Docker Compose | 单机部署，简化运维，支持快速回滚 |
| 前端持久化 | localStorage | 存 sessionId，刷新自动恢复，无需额外存储依赖 |
| 图片存储 | 本地磁盘 + Spring Boot 静态资源服务 | 单机部署场景下最简单，无需引入对象存储，成本可控 |

**架构分层**（后端内部）：

```
前端 Vue3
   │  X-Session-Id / X-Session-Status
   ▼
Controller 层（参数校验、限流、并发锁入口）
   ▼
Service 层
   ├── Agent 调度器（核心：Prompt 模板加载→变量替换→上下文组装→大模型调用→结果解析→容错降级）

   ├── 范文生成 Service
   ├── 批改 Service
   ├── 会话 Service
   └── 历史记录 Service
   ▼
Mapper 层（MyBatis-Plus → MySQL）＋ Redis 工具层（会话上下文 / 限流 / 分布式锁 / 模板缓存）
```

## 4. 核心业务设计

### 4.1 会话生命周期
- 前端生成 UUID v4 作为 sessionId，经 `X-Session-Id` 请求头传递；后端不主动建会话。
- 后端校验 UUID v4 格式，非法返回 400。
- 会话上下文存 Redis，TTL 7 天；所有响应携带 `X-Session-Status: active|expired`。
- 会话过期与图片存储 7 天对齐；历史记录查询**不校验会话状态**，仅校验 sessionId 格式。
- **孤儿会话处理**：若用户清空浏览器 localStorage，Redis 中会话上下文成为孤儿数据，由 Redis TTL 自动回收，无业务影响。
- **sessionId 安全审计**：后端首次使用 sessionId 时记录 `session:{sessionId}:meta`（包含 IP + User-Agent），后续请求校验是否匹配；仅记录不强制拦截，做安全审计日志，防止 sessionId 被滥用（如用户手动复制导致会话错乱）。

### 4.2 作文类型枚举
统一三种，动态注入不同评分标准：

| 枚举 | 含义 | 评分侧重 |
|------|------|----------|
| `EN1_PICTURE` | 英语一图画大作文 | 图画描述准确性、寓意提炼深度 |
| `EN2_CHART` | 英语二图表大作文 | 图表数据分析、趋势归纳能力 |
| `LETTER` | 应用文/小作文（一二通用） | 格式规范、交际得体性、信息完整性 |

类型继承规则：会话内已设定的类型作为批改默认值，可手动覆盖；未设定则强制选择。

### 4.3 Agent 调度核心（项目亮点）

**调用链**：
1. 根据 sessionId 首次锁定模板版本（灰度 `hash(sessionId) % 100`）。
2. 加载 Prompt 模板，进行 `{{essay_type}}`、`{{user_essay}}`、`{{history_summary}}`、`{{topic}}` 变量替换。
3. 组装上下文（滑动窗口策略）。
4. 调用大模型（按模板 Temperature）。
5. 解析返回 JSON。
6. 异常时重试 / 降级。

**上下文滑动窗口策略**：
- 固定保留：System Prompt + 当前题目 + 当前待批改作文 + 最近 2 轮完整对话。
- 超过 4 轮时，第 1 轮至第 (N-2) 轮交由 Agent 生成**覆盖式完整摘要**（非增量），摘要替换原始记录。
- 摘要生成在请求内同步完成，Token 计入本次总消耗。
- **摘要生成超时**：摘要调用超时阈值为 15 秒（可配置 `agent.summary.timeout`），超时后立即走降级截断，不等待直到失败。
- **摘要失败降级**：超时/失败 → 直接截断（丢弃最早两轮，保留最近 4 轮），响应标记 `summary_degraded: true`。

**容错降级**：
- 大模型返回格式异常 → 自动重试 1 次且 Temperature 降至 0.1；仍失败 → 降级返回"仅语法纠错"简化结果。
- OCR 空结果/乱码 → 重试 1 次；仍失败 → 提示手动输入，降级纯文本模式。
- 输出超长 → `max_tokens` 限制，截断并提示，前端折叠展示。

### 4.4 图片 OCR 手写作文批改
- 支持上传手写作文图片
- **图片上传限制**：支持 jpg、png、jpeg 格式，单张图片大小不超过 10MB，建议图片宽度不低于 1000px 以保证 OCR 识别准确率；超出限制时前端拦截并提示压缩后重试
- **上传失败处理**：网络超时或存储服务不可用时，提示"图片上传失败，请检查网络后重试"，支持重新上传，不降级
- 调用第三方 OCR 接口识别图片中的作文文本
- **OCR 异常处理**：OCR 服务返回空结果或乱码时，自动重试 1 次；仍失败则提示"图片识别失败，请手动输入文本"，降级到纯文本输入模式
- **OCR 识别结果校验（仅提示不拦截，允许校对后继续）**：
  1. 语言检测：英语字符占比低于 80% 时，提示"识别结果可能非英语内容，请校对修正后再提交"，但不阻断提交
  2. 长度校验：识别文本长度低于 10 字符时，提示"识别内容过短，请确认图片清晰度"
- **OCR 特殊字符**：识别结果中夹杂的数学符号、下划线等特殊字符在前端校对框中正常显示，不做特殊过滤
- 识别结果返回前端，支持用户人工校对修正识别错误
- **OCR 接口行为**：`POST /api/ocr/upload` 仅返回识别出的原始文本及单词级置信度（可选），前端展示供用户校对，**不完成批改**；校对确认后用户再调 `POST /api/essay/correct` 提交批改
- **OCR 置信度处理**：若 OCR 返回单词级置信度，前端校对框中置信度 < 70% 的单词标黄高亮，引导用户重点校对
- 校对确认后提交作文，**执行 4.5 定义的输入前置校验（拦截式）**，校验通过后执行批改流程
- 批改记录关联保存原始图片地址
- **校对校验**：提交时比对 OCR 原始识别文本与用户校对后文本的编辑距离，**双阈值判定**（同时满足时标记重度编辑）：编辑距离 > 30 字符 **且** 改动比例 > 20%（避免短作文误触），提示用户"改动较大，是否以当前文本为准？图片仅作参考"，并在记录中标记 `is_heavily_edited=true`
- **重度编辑差异化处理**：标记为 `is_heavily_edited` 的记录，批改时 Prompt 中降低图片参考权重，记录详情页显示"非原图批改"标签

### 4.5 输入前置校验（拦截式）
1. 非空：去首尾空白 ≥10 字符。
2. 语言检测：英文字符占比 ≥80%（分母=英文字符+非英文字母字符；标点/数字/空格/emoji 不计入）。
3. 词数上限：≤800 词。
4. 敏感词/恶意代码拦截：
   - 库选型：使用 `sensitive-words`（开源轻量级中文敏感词过滤库）或基于 Lucene 分词 + 自定义词表实现。
   - 词表管理：通过挂载配置文件实现词表调整；v1.0 热重载简化为重启服务（Docker Compose 重启即可），不在代码层面做动态加载，降低复杂度；v1.1 视需求决定是否实现真正的热重载。

### 4.6 历史记录重新批改
- 支持从历史详情页发起重新批改，**两种模式**：
  1. **原样重批**：直接使用原记录的题目与原文，不修改，用于验证 Agent 输出稳定性（前端提供"原样重批"按钮）
  2. **修改后重批**：用户可修改题目/原文后再提交，用于多轮迭代优化
- **接口参数区分**：`POST /api/essay/re-correct` 接收 `record_id`（必填）和可选的 `topic`、`user_essay`（未传则复用原记录）以及 `essay_type`（默认复用原记录）
- **批改行为**：
  - 不继承原作文的迭代上下文（争议标注等作文级数据重置）
  - 不清空 session 级词汇集（词汇集为 session 级别，跨作文共享）
  - 生成一条全新的历史记录，便于对比不同版本的得分差异
  - 视为一次新的批改请求，计入单 session 每分钟 5 次的限流配额

### 4.7 批改结果（JSON 结构化）
1. 总分 + 分项得分（内容完整性、语言准确性、词汇多样性、句式丰富度）。
2. 语法/用词错误定位。
3. 不足与修改建议。
4. 全文润色优化版本。
5. 可复用高级句型与表达提炼。

## 5. 数据库设计（MySQL）

### 5.1 `essay_record`（批改记录表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| session_id | VARCHAR(36) | 会话 ID |
| essay_type | VARCHAR(20) | 作文类型枚举 |
| topic | TEXT | 题目 |
| user_essay | TEXT | 学生原文 |
| result_json | TEXT | 批改结果 JSON |
| image_url | VARCHAR(255) | 原始图片地址（可空） |
| template_id | VARCHAR(64) | 本次使用的模板 ID |
| template_version | VARCHAR(20) | 模板版本号 |
| user_disputed | TINYINT | 争议标注（v1.0 预留字段，数据结构已就绪，v1.1 启用前端入口） |
| is_heavily_edited | TINYINT | 重度编辑标记（v1.0 启用：OCR 校对后文本与原识别文本编辑距离 > 30% 时为 1） |
| created_at | DATETIME | 创建时间 |

**索引设计**：
| 索引名 | 字段 | 类型 | 用途 |
|--------|------|------|------|
| `idx_session_id` | `session_id` | 普通 | 按会话查询历史记录 |
| `idx_session_created` | `session_id`, `created_at DESC` | 复合 | 分页查询优化，按会话+时间倒序 |
| `idx_template_version` | `template_id`, `template_version` | 复合 | 效果回溯统计，按模板版本分析 |

### 5.2 `prompt_template`（Prompt 模板表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| template_name | VARCHAR(100) | 模板名称 |
| version | VARCHAR(20) | 版本号 |
| content | TEXT | 模板内容（含占位符） |
| essay_type | VARCHAR(20) | 适用作文类型 |
| temperature | DECIMAL(3,2) | 默认温度 |
| max_tokens | INT | 最大输出 Token 数，便于按模板控制输出长度 |
| enabled | TINYINT | 是否启用 |

**索引设计**：
| 索引名 | 字段 | 类型 | 用途 |
|--------|------|------|------|
| `uk_name_version` | `template_name`, `version` | 唯一 | 同一模板多版本不重复 |

> Redis 存储：`session:{sessionId}` 会话上下文、`lock:session:{sessionId}` 分布式锁、限流计数、模板缓存。

## 6. 接口设计（摘要）

| 方法 | 路径 | 说明 | 调用大模型 | 限流 |

## 7. 非功能需求实现

| 需求 | 实现方案 |
|------|----------|
| Token 控制 | 滑动窗口截断 + 摘要覆盖式生成 + 模板化 + 输入精简 |
| 响应速度 | 常规轮次 10 秒内；触发摘要生成的轮次需连续执行两次大模型调用（摘要生成+作文批改），允许超出 10 秒，前端对该轮次加 loading 提示；摘要生成超时阈值 15 秒（可配置），超时立即降级截断 |
| 并发控制 | Redis 分布式锁 `lock:session:{id}`，超时 60 秒，串行化执行 |
| 限流 | 所有调用 Agent 的接口共用配额，单 session 每分钟 5 次，超限返回 429；全局 TPM 限流采用滑动窗口（Redis Sorted Set 记录每次请求的 Token 消耗和时间戳，`ZREMRANGEBYSCORE` 清理 60 秒前数据，`ZSCORE` 求和后判断是否超限），上限设为账号限制的 80%，超限返回 503 {"code": "TOO_MANY_REQUESTS", "message": "系统繁忙，请稍后重试"} |
| 安全性 | 参数校验、敏感词拦截（`sensitive-words` 库或 Lucene 分词 + 自定义词表）、API 密钥配置化、Markdown 导出使用 OWASP Java HTML Sanitizer 净化 user_essay 和 result_json 文本字段，枚举值不净化 |
| 会话过期处理 | 前端检测到响应头 `X-Session-Status: expired` 时弹出 Toast 提示"会话已过期（7 天），历史记录仍可查看，新建批改将开启新会话"，生成新 sessionId |
| 日志监控 | Agent 成功率、响应时间、Token 消耗、OCR 成功率、模板版本分布、失败率告警 |
| 数据备份 | MySQL 定期备份；Redis 为临时缓存，丢失仅影响上下文 |

## 8. 设计评审记录

| 序号 | 评审问题 | 整改方案 |
|------|----------|----------|
| 1 | 摘要生成同步调用导致响应时间翻倍，可能超过 10 秒目标 | 触发摘要生成的轮次不做 10 秒 SLA 承诺，前端对该轮次加 loading 提示；常规轮次仍满足 10 秒；摘要生成超时阈值 15 秒（可配置），超时立即降级截断 |
| 2 | OCR 识别 + 用户校对后提交，重复走前置校验是否冗余 | 不冗余：OCR 阶段仅提示不拦截，用户校对后提交时才执行拦截式前置校验，两道校验语义不同 |
| 3 | 灰度分流按 `hash(sessionId) % 100` 取模，模板版本切换后同一会话可能评分不一致 | 会话首次调用时锁定模板版本并写入 Redis，该会话后续请求沿用同一版本，不受灰度规则变更影响 |
| 4 | 图片过期后前端可能出现 404 | 历史详情页先检查 `image_url` 是否为空（定时任务已清理文件并置空），为空则展示"图片已过期"占位图，与 7 天策略对齐 |
| 5 | 用户清空 localStorage 后 Redis 存在孤儿会话 | 由 Redis TTL 自动回收，无业务影响，无需额外处理 |
| 6 | 敏感词库选型未明确 | 使用 `sensitive-words` 开源库或基于 Lucene 分词 + 自定义词表；词表通过挂载配置文件管理；v1.0 热重载简化为重启服务（Docker Compose 重启即可），v1.1 视需求决定是否实现真正的热重载 |
| 7 | OCR 置信度未说明前端展示规则 | 若 OCR 返回单词级置信度，前端校对框中置信度 < 70% 的单词标黄高亮，引导用户重点校对 |
| 8 | Markdown Sanitize 库未指定 | 使用 OWASP Java HTML Sanitizer，仅净化 user_essay 和 result_json 文本字段，枚举值不净化 |
| 9 | 前端如何解析会话过期 | 检测响应头 `X-Session-Status: expired` 时弹出 Toast 提示"会话已过期（7 天），历史记录仍可查看，新建批改将开启新会话"，生成新 sessionId |
| 10 | 编辑距离 30% 比例阈值对短作文误触 | 改为双阈值判定：编辑距离 > 30 字符 **且** 改动比例 > 20% 同时满足时才标记重度编辑 |
| 11 | 多 session 并发可能打爆账号级 TPM | 补充全局 TPM 限流采用滑动窗口（Redis Sorted Set 记录每次请求的 Token 消耗和时间戳，`ZREMRANGEBYSCORE` 清理 60 秒前数据，`ZSCORE` 求和后判断是否超限），上限设为账号限制的 80%，超限返回 503 |
| 12 | sessionId 被篡改或复制可能导致会话错乱 | 后端首次使用 sessionId 时记录 `session:{sessionId}:meta`（包含 IP + User-Agent），后续请求校验是否匹配；仅记录不强制拦截，做安全审计日志 |

## 9. 版本规划

### v1.0（当前）
随机题生成、自定义题范文、文本批改、图片 OCR 批改、多轮迭代、会话管理、报告导出、历史记录、评分标准适配、Prompt 模板化，以及生词本/争议标注的数据结构预留。

### v1.1（规划）
生词/好词收藏前端入口、争议标注前端入口、敏感词误杀申诉、批改结果对比模式、敏感词热重载（视需求决定）、批改结果缓存（相同内容缓存 24 小时）、得分趋势图（最近 10 次总分折线图）、错误类型分类统计（语法/词汇/拼写/逻辑高频聚合）。

### v1.0 可选优化（技术债务）
前端 OCR 图片压缩（Canvas 压缩至 2000px 宽，降低存储传输成本）。

- ❌ 通用闲聊、作文收藏/标签/点赞等纯 CRUD
- ❌ 使用 LangChain 等现成 Agent 框架
- ❌ 历史记录删除、敏感词申诉（v1.1 规划）
